# 业务规则与算法规格

版本：2.0 · 原始基线：2026-10-10 · 修订：2026-10-11 · 状态：当前需求与实现基线。

## BR-001 物料、BOM 与版本

- 类型：FINISHED、SEMI、RAW。只有前两类可销售/作为 BOM 父项；直接组件只能是 SEMI 或 RAW。
- BOM 状态 DRAFT、ACTIVE、RETIRED；每物料最多一个 ACTIVE 默认版本。激活后结构不可原地修改，复制为新版本；历史父 BOM 可继续引用旧不可变版本。
- 子项为 SEMI 时必须指向同物料的制造 BOM；RAW 不得有子 BOM。确认销售时冻结整个选定版本图。
- 除版本节点无环检查外，还禁止路径中重复物料，避免不同版本绕过 A→B→A 限制。迭代 DFS 维护当前路径，不把其他分支共享节点误当循环。
- 激活父 BOM 前保证所有子 BOM 完整可用；停用物料阻止新增需求，不影响已有历史及在制单据。

## BR-002 数量、精度与取整

单位精度由 Unit 决定：件/瓶/排/箱/个为 0，kg/L 等默认最多 6 位。一个物料只有一个单位，本期无通用单位换算；“排→瓶”通过 BOM 表达。

`所需子项数量 = 父项计划产量 ÷ BOM 基准产量 × BOM 子项用量`。

内部用有理数计算比例；持久化数量用放大 10^6 的 64 位整数（qty_u），API 用十进制字符串，不用 JSON 浮点。数量上限为 1,000,000,000 单位，溢出或非法精度拒绝。

精度不足时向上取整到对应单位最小步长 `10^(-decimal_places)`：计件为1，精度6的连续单位为0.000001。计划须同时显示精确理论量、计划量和差额。先确定每张消费单的计划产量，再计算其直接组件需求并按组件单位向上取整；供应单汇总这些合法需求数量。生产量取整后必须按新产量向下重新展开用料，不能只给父单多加数量。向销售和父单分配量不得超过计划量；未分配的产出余量单列 rounding_surplus，不作为库存、不擅自增加销售数量。组件需求取整差额和产出未分配余量是两种不同信息，不重复计量。

相同父物料先合并，再按合并后的父单计算组件需求；不同父单的组件需求分别合法化后才汇总供应需求。例如 BOM 生产2件需1个组件：合并生产2件需1个组件，拆成两张各1件的父单则每张需要1个组件，总计2个，须明示取整导致的额外用料。人工拆批必须使用合法单位步长，重新校验全部下级分配与用料。以上仅为边界测试算例，不规定最终演示数据。

## BR-003 销售、优先级及需求覆盖

- 单状态：DRAFT、CONFIRMED、PRODUCTION_COMPLETED、CANCELLED。
- 优先级持久化及API使用HIGH/NORMAL/LOW字符串，默认NORMAL。行可覆盖单头，确认后固化；用于需求分组，不是强制执行顺序。保持LOW也可手工先完成，不生成可信交期预测。
- 创建或编辑销售草稿时，商品必须为已有且启用的成品或已允许销售的半成品，并具有完整可用的制造 BOM；不存在的物料、原料、无 BOM 或仅有草稿 BOM 的商品禁止保存，失败整单回滚。显式选择允许 ACTIVE / RETIRED 版本；未指定版本必须存在 ACTIVE 默认版本，确认时解析并冻结默认版本。
- 确认时重新校验整张单全部制造 BOM；任一错误整张确认失败。
- 确认销售与刷新当前未确认建议在同一业务操作内完成；已有正式计划不参与重组。超规模失败可回到草稿修正，不留下半确认状态。
- 销售确认后可分多次安排；“未安排数量 = 行订购量 − 有效正式销售分配量”。无库存抵扣，不把中途进度当产出抵扣。
- 未覆盖数量必须单独展示；全部需求正式覆盖且相关顶层生产单全部完成才标记 PRODUCTION_COMPLETED。
- 已有历史销售确认时间保留；取消和撤销不硬删除，原因必填。

## BR-004 计划及合并

系统仅维护一个当前可编辑建议版本；每次刷新使旧版本 SUPERSEDED，正式计划 CONFIRMED，已撤销为 REVOKED。建议状态 DRAFT。

1. 读取所有已确认销售行尚未正式安排的数量、版本与优先级。
2. 迭代展开明确 BOM 版本，保留来源销售行与路径数量。
3. 按 `(item_id, bom_version_id, priority)` 分组；不同 SKU、版本或优先级不可合并。无产线、库存、交期窗口过滤。
4. 先在 BOM 物料 DAG 的上层聚合并确定产量/取整，再向下传播实际用量；共享下级收齐所有上级需求后再聚合，避免漏掉取整带来的用料。
5. 建立建议节点、供应边、销售根分配、原料明细、来源解释和取整余量。
6. 用户拆合调整后校验所有供应边和数量，必要时重新展开受影响下游；未经重新校验不能确认。
7. 设置有子单节点的 w（实现默认 60%），叶节点必须为 null。用户可修改，确认后冻结。
8. 确认前重新比较全局数据修订号、销售剩余量和建议版本；失效返回 STALE_PLAN，不能强行覆盖。

建议允许拆分 sales allocation，因此一销售行可对应多生产单；一次确认只确认当前建议版本的完整图。需要分次安排时可减少某些销售行本次覆盖量，其余保留待排。任何图中节点都必须可沿依赖路径追溯至至少一个本次销售根，禁止孤立生产。

## BR-005 分配、批次和层级

正式确认原子生成：ProductionOrder（批次同表）、ProductionDependency、SalesAllocation、MaterialRequirement、快照与日志。

数量规则对每个供应生产单成立：

`计划产量 = 对父生产单的分配量合计 + 对销售行的直接分配量合计 + 明示计划余量`。

父单每种制造组件的入边数量合计必须满足其 BOM 展开的计划用量；原料用量独立保存。相同供应单→消费单只保留一条聚合边；同一销售行→生产单只保留一条销售分配。边数量单位永远是供应单物料单位。不同单位不得合计。

批次格式：`P{YYYYMMDD}-{全局计划序号6位}-L{层级至少2位}-{图内节点序号4位}`。序号可扩展，不截断、不回绕；唯一性由数据库确保。日期以确认时上海日期计算。重置也不复用全局序号。

冻结层级：从本计划所有销售根沿消费单→供应单传播，取抵达节点的最大路径深度，根初值为 0，顶层编号为L00。共享节点可同时是销售根又是别的根的下级，因此编号层级不等于它相对每张销售单的深度。批次详情展示所有实际路径；编号不用于反推关联。

父单手工开工时锁定其所有入边的使用确认时间。w=100% 自动完成时自动确认入边使用；取消保留量达到完成时也确认有效入边；直接销售分配在生产完成时确认。普通结构自正式确认即冻结；取消可按BR-010缩量，保留原快照和审计。使用确认仅说明由“计划分配”进入“已确认使用”。

追溯代表系统确认的批次混合关系。一个输出批次汇合多个输入批次后，其所有销售去向都应能追溯到这些输入批次；没有逐瓶序列号，不能声称某一瓶准确来自某个混料子批次。

## BR-006 状态机和开工门槛

生产单状态 WAITING、READY、IN_PROGRESS、COMPLETED、REVOKED；无单独创建用户状态。

判定顺序：已撤销记录维持REVOKED；有效直接子单全部完成且精确T=1→COMPLETED；否则，已手工开工→IN_PROGRESS；未开工且子单全部完成（含无子单）→READY；其他→WAITING。合法取消及纠错不得使已开工父单出现未完成有效子单。完成方式为HUMAN（人工）、AUTO（常规自动）、CANCEL（取消进度下限达到100%）。

叶节点初始 READY、M=0。有子单的单据只检查生产子单状态，不检查原料。READY 手工开始后设 actual_started_at，M 仍为 0。只有 IN_PROGRESS 可以常规手工修改 M。

COMPLETED 的修正使用专门 correct-progress 动作，不复用常规更新。w=100% 节点没有自身加工，不允许手工开始或输入 M。自动完成不虚构 actual_started_at，记录 completion_mode=AUTO 与 completed_at。

## BR-007 总进度、销售进度和传播

M、w 的输入精度为 0.01%，保存 basis points：0..10000。归一化后为 0..1。

常规基础进度B：叶节点 `B=M`；非叶节点 `B=w×(ΣT_child / distinct_child_count)+(1−w)×M`。

取消记账下限C：`C=保留完成量/当前计划量`，默认0。实际总进度 `T=min(1,max(B,C))`。子单采用其精确T（含各自取消记账）参与上级公式；该规则统一适用于所有层级。

直接子单按 ProductionOrder ID 去重，分配数量和 BOM 用量均不作权重。等待期间 M 必须为 0；T 可以增长但不可手工覆盖。

为避免多级舍入，内部 T 使用有理数（整数分子/分母）；持久化快照用两个十进制整数字符串字段。显示到两位小数，ROUND_HALF_UP；非 COMPLETED 状态显示最多 99.99%。真实完成依据状态条件，不依据格式化数值。

`SalesProgress = ΣT_distinct_root / root_count`；无关联生产单时为 0。行用该行关联的根集合，单头用所有行根集合的并集，不能再平均行百分比。部分安排时展示“已安排生产进度”和待排数量；即使已关联根全完成，只要存在待排量，销售状态仍 CONFIRMED，显示“已安排部分 100%，尚有待排需求”，不声称全单完成。

一个被直接销售的共享半成品单，在购买该半成品的销售根集合中计入，在购买上级成品的根集合中不计入，除非同一销售单还直接购买该半成品。

进度更新在一个写事务内：校验版本和依赖→记录 M→从受影响节点向所有消费方逆向拓扑重算→处理自动完成/使用确认→重算受影响销售→追加事件/日志→提交。UI 只消费提交后的结果，不能看到半条链已更新。

## BR-008 回退与更正

用户可修正已开工节点的 M（0..100%），必须填写原因；完成节点可经 correct-progress 降到 100% 以下。

降低 M 前，遍历所有直接/间接消费方；任一下游 actual_started_at 非空（包括已手工完成）则拒绝 DOWNSTREAM_STARTED。全自动 w=100% 完成节点不是手工开工，允许随供应修正自动退回 WAITING；清除当前 completed_at/自动使用确认状态，但历史日志保留。

修正不清除本节点首次 actual_started_at。如果曾有销售生产完成，会退回 CONFIRMED 并清除当前 production_completed_at；对应尚不再完成的供应单销售分配 fulfillment_confirmed_at 也清除，历史完成事件保留。无发货模块，故允许这种演示更正。

## BR-009 原料及使用确认

原料行保留物料、单位、BOM 行路径、理论及计划需求量。原料不计入 child_count，不设置进度、不生成批次、不触发采购、不阻止开工。

本期不模拟部分合格产出：M=50% 不产生可交付一半数量；取消时按T折算完成量仅用于内部进度重算，不形成部分库存或交付。完成意味着当前剩余计划量完成。质量、报废、返工、欠产、额外超产均不在本期。

## BR-010 撤销、取消和重建

正式计划的普通结构编辑仍采用未开工整计划撤销重建；销售取消是专门的数量缩减操作，允许已经开工或完成的销售单取消，不撤销其他销售需要的共享批次。

先返回影响预览：计划、生产批次、销售单及逐批旧/新数量。用户确认后，在同一事务内移除该销售的分配量；独占批次标 REVOKED，保留原数量作为历史；共享批次保留批次号及优先级，按剩余分配量缩减数量。拆过的销售逐分配记录扣量，其他销售分配不变。保留取消前后的完整审计和无效依赖历史，不硬删除生产单。

由消费者向供应者按剩余实际产量重新展开 BOM，逐消费者按单位步长向上取整。一个组件由多张子单供应时，按原边数量比例分配剩余需要量，采用最大余数法按单位步长分配，余数相同按依赖 ID 排序；零需求边标无效，零需求批次撤销，仍有直接销售或其他父单需求的子单保留。原料需求同步更新，不生成库存。

每个缩量批次保留 `已完成量 = 取消前计划数量 × 取消前总进度`。进度下限为 `min(已完成量 ÷ 新计划数量, 100%)`，超出的已完成量丢弃，不作为库存。自身进度按旧/新数量比例缩放，上限100%；总进度为常规子单公式与保留量进度下限的较大值，上限100%。使用精确有理数存储保留量，避免多次取消及多级传播的舍入误差。

例如 100件完成60件、取消40件，剩60件完成；100件完成30件、取消40件，剩60件进度50%。父单即使未手工开工，也可能由取消记账达到100%；但完成状态与开工仍要求全部有效直接子单已完成。取消记账导致完成使用 CANCEL 完成方式。下级各自基于取消前已完成量和重算后的需求同步推理，销售单继续以有效顶层批次等权反馈。

后续人工纠错依然要求开工、所有子单完成、下游尚未手工开工，并填写原因；显式纠错清除该单的取消进度下限，再按新自身进度重算。整计划撤销的未开工限制保持不变。取消预览令牌在任何相关变化后失效，幂等重放不会重复扣量。

## BR-011 重置、历史与重试

重置需要一次预览及一次显式确认，当前UI只支持清空业务数据（scenario_code=null）。蒜蓉酱初始场景已按18文档通过显式命令导入并提供v2备份；快速复演使用停机恢复及重新生成建议，不是重置接口的一键场景菜单。测试环境的临时夹具不导入运行库。重置保留全局编号序列、递增 dataset_epoch，写入新的重置日志。旧日志随演示数据清除，这一例外在确认弹窗明确告知。

所有写请求携带 dataset_epoch、实体 expected_version、Idempotency-Key。同 key 同请求返回原结果，同 key 不同内容拒绝；跨数据世代的旧请求一律 STALE_EPOCH。事务失败不留下成功幂等记录。日志不含账号或操作人。

半成品销售资格：新建 SEMI 默认 is_sellable=false；FINISHED 固定可销售，RAW 固定不可销售。关闭半成品销售资格不影响 BOM 使用及已经确认的销售、生产和批次历史，但新增、编辑销售草稿及草稿确认均重新校验资格。存量自定义半成品升级时保留旧销售能力；演示中瓶装蒜蓉酱可销售，蒜蓉酱中间料（份）不可销售。
