# 变更管理、风险和实现约定

版本：2.1 · 原始基线：2026-10-10 · 修订：2026-10-11 · 状态：当前需求与实现基线。

## 已确认业务约束

三类物料、无限固定层级BOM、制造项必须有生产单、跨销售合并、人工确认、所有直接子单完成才开工、进度递归贡献、销售顶层等权、独立批次与双向追溯、无库存/产能/权限、单容器和指定技术栈均来自已确认讨论。

用户已接受此前补齐的单位、快照、幂等、回退、撤销、取整展示、实际完成状态和重置等规则。后续已确认：销售草稿强制可用BOM；LOW优先级不阻止手工先完成；18演示数据显式导入及备份；销售取消按实际分配缩量，保留已完成量重算各级进度。开发完成前暂缓演示数据的约定已兑现，开发完成后用户另行授权了18场景。

## 实现约定登记

以下是为让开发可执行而提出的设计选择，不伪装成用户逐字指定的需求。修改时核对影响即可，无需另加权限或批准流程。

| 编号 | 约定 | 原因/影响 |
|---|---|---|
| DC-001 | 同类合并以相同SKU+BOM版本+优先级为键 | 不把相同类别不同规格混产 |
| DC-002 | 默认非叶子单占比60%，可在建议阶段改0～100%；叶无占比 | 便于初始输入，正式确认后锁定 |
| DC-003 | HIGH/NORMAL/LOW三档，默认NORMAL | 不增加复杂优先级管理界面 |
| DC-004 | 部分待排时进度只描述已安排部分，必须显示未安排量 | 保留用户等权算法，又不误称全单完成 |
| DC-005 | 建议整图确认；正式修改采用整计划撤销重建 | 普通编辑按此规则；销售取消按BR-010局部扣量且保留共享单，影响范围须预览 |
| DC-006 | 批次冻结层级取本计划销售根到该节点的最大路径深度 | 共享节点不能只有唯一业务父级，实际路径另外显示 |
| DC-007 | 数量最多6位小数，进度输入0.01%，总进度精确有理数 | 避免多层舍入及SQLite浮点差异 |
| DC-008 | 根目录Compose首次运行空业务库，只初始化单位/系统设置 | 首次启动不自动灌入业务；18场景显式导入；测试数据隔离 |
| DC-009 | 1个同步应用worker、同源静态/API、同步计算 | 满足轻量单容器，不新增基础服务 |
| DC-010 | 本期无通用单位换算、单件序列号、部分交付 | BOM表达包装换算；追溯以批次混合关系为粒度 |
| DC-011 | 先对每消费单组件需求取合法单位精度，再聚合供应 | 不产生半个计件分配；拆单可能增加用料，必须提示 |
| DC-012 | 相同边/销售行关联聚合，销售头对根ID去重 | 防止重复贡献进度及重复追溯计数 |
| DC-013 | 销售草稿强制完整可用BOM | 无临时产品；未指定版本要求ACTIVE，显式允许ACTIVE/RETIRED |
| DC-014 | 取消精确保留完成量、进度下限与常规公式取大 | 多级同期缩量，不计库存；可未手工开工完成，仍有依赖门槛 |
| DC-015 | 取消时零需求依赖保留active=false，销售分配置0 | 记录前后审计，历史批次可追溯，不误计当前供应 |

## 风险与处理

| 风险 | 处理和验证 |
|---|---|
| 合并生产图被误做成单父树 | 独立依赖表，多父级/多路径测试TC-025/029/033 |
| 总进度达到显示100即放行 | 完成状态独立判断，非完成显示上限99.99，TC-024 |
| 拆单改变等权平均分母 | 普通拆合仅在确认前；取消后有效子单数可能变化，需重算并解释参与平均的节点 |
| 取整造成数量或用料不守恒 | 自上向下重新展开，区分组件取整差额与未分配产出余量 |
| 共享单取消影响其他销售 | 销售取消逐批数量预览+原子扣量；保留共享单及完成量、重算子单，TC-035 |
| 无库存却误用进度当可用产量 | 百分比不换算可交付量，严格整单放行 |
| SQLite并发锁和重试造成重复单据 | 短事务、单worker、版本/幂等、TC-015/039 |
| 无固定层级引发超大展开 | 迭代遍历、节点/边预算、显式失败、不截断 |
| 字符串批次层级无法表达共享 | 冻结编号+实际路径，不通过解析编号追溯 |
| 过早填充演示场景成为额外范围 | 测试夹具与最终演示数据隔离，18显式授权后导入；默认启动不灌入 |
| 文档完整但应用未验证 | 文档检查与软件测试结果分开，不把设计表当通过报告 |

## 变更流程

记录变更原因→定位FR/NFR和BR→更新相关算法、ER/API/页面→更新测试及追踪矩阵→实施→实际验证。只变UI文案不需要扩大数据库；涉及正式单据含义的变化必须说明历史数据如何迁移。

需求冲突时按最近用户明确说明处理，保持其他已确认目标；不因补充一句就丢失原始范围。

锁文件、环境、性能已验证，产品及演示初始数据已按18确定；讲解脚本、一键场景菜单尚未交付。当前不存在必须通过账号/权限才能推进的事项。

## 当前部署与初始化口径

根目录Compose空库仅初始化单位和系统配置；快速部署包与Railway首次空库加载v3初始演示种子，之后重启或升级保留已有数据，绝不自动重置。当前基线包含0001～0005迁移、20张确认销售和41条明细，不含中间料直销。

本地快速部署与恢复见 [deploy](../deploy/README.md)，Railway单实例与/data持久化卷见 [Railway](../deploy/railway/README.md)。升级只迁移结构和销售资格，不取消历史订单、不改现有生产进度。
