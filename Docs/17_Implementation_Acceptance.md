## 可重复验证

```sh
make check
make e2e
.venv/bin/python scripts/verify_container.py
.venv/bin/python scripts/benchmark.py
```

- Python：61 项测试通过（含 4 项原环境冒烟测试，以及成品/半成品销售草稿强制 BOM 与编辑失败回滚测试）；业务、API、数据库、恢复、100 层制造链及分数精度均有实际断言。
- 生成式测试：30 个不同的子单数量、进度及贡献比例组合，精确结果与独立 Fraction 算式一致。
- 前端单元：5 项通过，覆盖组件挂载、CSRF/epoch/幂等请求和错误反馈。
- Chromium：3 个端到端用例，实际执行新建/编辑/删除物料及销售→排产拆合→生产→追溯，无页面脚本错误。
- Ruff、ESLint、Prettier、TypeScript、Vite 生产构建、Django 检查、迁移一致性及依赖检查由 make check 验证。
- 容器实际构建和运行；并发相同版本两次写入恰好一个 200、一个 409；重启/替换保留批次，恢复找回原进度，无网络容器可提供页面和 API。

测试数量与 TC 数量不是一一对应；一项测试可同时覆盖多个 TC，生成式测试还运行多个样本。46 项设计用例的证据映射见下一节。

## 性能与部署证据

压测脚本创建独立临时数据库，使用实际 SQLite 与领域服务；查询包含 Django HTTP 中间件。每类操作预热 5 次、采样 30 次，正式确认样本在事务结束时回滚，不堆积历史记录。

实际 Docker 容器限制为 2 CPU / 4GB，数据规模为 100 张销售单、500 行、2000 个生产节点、5000 条依赖边。每项采样 30 次，失败率为 0，全部达到验收目标。

| 操作 | 中位数（秒） | P95（秒） | 验收上限（秒） |
|---|---:|---:|---:|
| 销售查询 | 0.1589 | 0.1808 | 1 |
| 排产建议 | 0.4133 | 0.4529 | 5 |
| 正式确认 | 1.1489 | 1.1835 | 5 |
| 进度重算 | 0.6076 | 0.6350 | 2 |
| 生产查询 | 0.0028 | 0.0031 | 1 |

原始结果见 [受限容器压测报告](benchmark-container.json)，部署验证见 [容器验收报告](container-verification.json)。查询使用 Django 测试客户端，不包含浏览器到服务的网络耗时；结果对应本次本机 Docker 环境，不是任意硬件的性能保证。
