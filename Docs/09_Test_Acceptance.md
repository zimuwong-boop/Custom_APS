# 测试计划与验收用例

版本：2.1 · 原始基线：2026-10-10 · 修订：2026-10-11 · 状态：当前需求与实现基线。

## 策略

领域单元测试验证图、数量、分配和公式；数据库/API 集成测试验证事务、版本、幂等和约束；浏览器端到端测试验证演示路径和禁用操作；单容器验收验证首次启动、持久化、恢复与离线运行。

每个用例使用独立 SQLite 临时库/数据世代。不能以接口 mock 代替数据库事务测试。人工截图说明展示效果，不能替代数值断言。固定随机种子、夹具版本、时区和序号初始值可重现结果。规则夹具始终隔离；用户后来授权的18演示数据另行导入。当前状态副本复核见19/20，不替代隔离回归。

| TC-009 | 连续单位需要1/3kg；分拆合法计件批次 | 向上取到0.333334kg并显示差额；下级按实际计划量重算；拆批数量守恒 |
| TC-010 | 销售原料/不存在商品；制造项无BOM、仅草稿BOM；有效BOM；草稿编辑更换无BOM商品 | 无效创建/编辑立即拒绝且回滚；可用BOM制造项可保存，确认重新校验并冻结 |

| TC-013 | 临时测试需求324件拆200/124，分配见13测试夹具 | 所有制造节点存在；销售/父单分配和计划量守恒；原料无生产单 |
| TC-014 | 建议有遗漏边、多分配、无来源节点、错误物料 | 返回明确 violations，不能确认 |
| TC-015 | 同计划确认提交两次、同key改内容、重复刷新销售 | 一套生产单/批次；冲突拒绝；已安排数量不重复排产 |
| TC-016 | 保存建议后新销售/BOM可用性变化，再确认旧建议 | STALE_PLAN，无半套单据；用户刷新后可确认 |
| TC-017 | 子单未完成时直接调用父单start/progress | 后端拒绝，即使绕过前端禁用也无副作用 |
| TC-018 | 只有原料的生产单确认、开始、M调60 | 初始READY，开始后IN_PROGRESS，总进度60；原料不阻塞/不计平均 |
| TC-019 | w=60%，唯一子T=60%，父M=0 | 父T=36%，WAITING，禁止手工加工 |
| TC-020 | w=60%，子T分别60/20 | 平均40，父T=24%，数量不同也不改变等权结果 |
| TC-021 | 子全完成、w=60%、父M=0/50/100 | 依次总进度60/80/100；READY/IN_PROGRESS/COMPLETED，开工须显式操作 |
| TC-022 | 子未全完成w=0；子全完成w=100 | w0总进度0但仍阻塞；w100自动完成、无actual_started_at、自动确认入边 |
| TC-023 | A w60→B w60→C叶100 | B为60且READY，A为36且WAITING；没有用显示舍入值传播 |
| TC-024 | 未真正完成但数学显示舍入到100；多层分数 | 显示最多99.99，不误标完成；精确分子/分母匹配独立计算 |
| TC-025 | 共享B分给两个父单，其中一份分量已足但B仅50% | 两父单仍不能开工；B整单完成才放行 |
| TC-026 | 已完成节点回退，无手工开工下游；有手工开工下游 | 前者成功并回算父/销售；后者DOWNSTREAM_STARTED，全事务无变化 |
| TC-027 | w100自动完成链，下层合法回退 | 自动节点退回WAITING，当前完成/使用确认撤回，历史事件保留 |
| TC-028 | 销售顶层进度36、60、90；两行引用同一根 | 销售62%；重复根只算一次，不能平均行百分比 |
| TC-029 | 同批次B为直接销售根，又是A的子单 | 买B的销售用B进度，买A的销售只用A；同时买A/B的单两根都计入 |
| TC-030 | 一销售部分安排且已关联生产全完成；完全未安排 | 前者显示已安排部分100%与待排量但未整单完成；后者0%待排 |
| TC-031 | 本级M=50%，查询可交付量 | 不返回由百分比换算的部分可交付量；销售最终状态为生产完成而非已发货 |
| TC-032 | 多层发号、共享节点不同路径、撤销后重建 | 批次唯一、冻结层级按规则；实际路径独立展示；新批次不复用旧号 |
| TC-033 | 临时夹具B1分120/80，B2分100/24 | 精确守恒；父单A2追溯B1+B2；B2反查相关包装销售及直接半成品销售；数量单位正确 |
| TC-034 | 完成后更改主数据，再查追溯与反向销售 | 历史快照、分配、批次完整，不依赖实时BOM重新推导 |
| TC-035 | 未开工共享计划取消一个销售；计划内有开工再取消 | 两者均预览后原子扣除销售分配、保留共享批次，重算子单及进度；无误删、无重复扣量 |
| TC-036 | 取消/撤销子单尝试让父单解锁；正式单PATCH数量占比 | 普通PATCH和无剩余需求子单的手工撤销不能绕过门槛；销售取消按BR-010重算有效边，保留完成量可使剩余批次完成 |
| TC-037 | 预览后另一操作改变版本，继续撤销/重置 | STALE_PREVIEW，要求重新预览；取消弹窗不改数据 |
| TC-038 | 无账号打开各页面及执行演示 | 无登录、角色、操作人字段；CSRF不是登录流程 |
| TC-039 | 进度写入中模拟异常；两个客户端同版本修改 | 异常全回滚含日志/幂等；并发仅一个成功，另一个409 |
| TC-040 | 重置后旧页面进度请求；重复发号；取消重置 | STALE_EPOCH；编号不复用；取消重置无数据变化 |
| TC-041 | 点击进度更新、切换销售页、查看日志/公式/阻塞 | 相关页面取到同一提交结果；日志有前后值与时间，无操作人 |
| TC-042 | 新库启动、写入临时数据、重启容器、替换同版本镜像 | 新库仅基础配置；重启/替换保留数据且不重复加载业务数据 |
| TC-043 | 备份后修改，恢复备份，故意损坏/错误权限 | 正常恢复原进度/批次；损坏或不可写时ready失败，live可正常 |
| TC-044 | 构建后断网运行，浏览器执行完整脚本 | 静态资源/API可用，无CDN、外部登录或运行时云依赖 |
| TC-045 | NFR-006规模压测，5次热身后30次采样 | 记录机器配置、节点/边数、p95及失败率，满足目标或提出明确变更 |
| TC-046 | 中文、单位、上海日期跨UTC日界线、桌面两尺寸 | 时间/批次日期正确；列表可滚动、状态不只用颜色、空错加载均可识别 |

TC-008 按 BR-002 执行：每张消费单的组件需求先取整到合法单位步长，再汇总供应需求；不存非法半个计件分配。额外计划用料必须显示，不解释为库存或实际报废。

## 不变量测试

随机生成小型无环BOM/生产图，验证：

1. 每生产节点产量=有效父单分配+直接销售分配+明示余量。
2. 每父单制造组件需求被完整覆盖，每销售行覆盖≤订购量。
3. 合并/拆分前后销售需求不变，无孤立制造节点、无环。
4. 非叶 w∈[0,1] 且输入合法时 T∈[0,1]；子进度单调增加且自身不变时总进度不下降。
5. 依赖未完成时不能手工开工；一个操作失败时所有业务表和缓存保持原值。
6. 批次唯一且所有历史追溯路径仍可查询（明确演示重置除外）。

## 2.1补充验收口径（沿用原编号）

- TC-010覆盖创建与编辑销售草稿的强制可用BOM，不只验证确认阶段。
- TC-011同时验证LOW不阻止手工先完成；新订单形成新草稿，不能追加冻结计划，实际证据见19。
- TC-035覆盖100/60取消40→100%、100/30取消40→50%、超出量忽略、多次取消32/60→32/40、拆分根及共享子单、已开工/已完成销售、原料需求重展、批次号不变、其他销售全覆盖。
- TC-036验证零需求批次REVOKED不等于完成；有需求父单仍按全部有效子单完成的门槛。取消记账可使未手工开工的剩余父单完成，不能用普通PATCH绕过。
- TC-037及TC-039同时覆盖取消预览过期、幂等不重复扣量、缩量失败后数量/分配/状态/日志全回滚。
- TC-043恢复当前结构兼容的v3初始备份；旧结构原备份保留为历史，不直接交给当前严格迁移校验的恢复工具。

当前实测为61项Python测试、5项前端单元、3项浏览器用例；不是46个设计TC的逐一数量对应。取消截图及当前运行库副本证据见 [20](20_Sales_Cancellation.md)。

TC-010补充半成品默认禁售、开启后允许销售、关闭后草稿确认失败且事务回滚，以及已确认订单不受资格关闭影响；TC-001覆盖非布尔值及原料开启销售资格被拒绝。首次启动验收区分根目录Compose的空业务库与快速部署包、Railway的初始演示种子。
