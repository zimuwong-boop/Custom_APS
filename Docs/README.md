## 使用约定

1. 用户已经接受的业务规则以 `02_requirements.md` 为需求基线，算法解释以 `03_Business_Rules.md` 为准。
2. 数据库、API、编号格式、默认占比和测试规模属于本次制定的**实现约定**；不是用户额外提出的业务需求。集中登记在 [14](14_Change_Risks.md)，可在不改变业务含义的前提下修订。
3. 冲突不得静默处理：更新需求或设计，补充追踪矩阵及测试，然后实施。
4. 全文“单据完成”默认为生产完成，不是发货或结算完成。
5. UML 中的用户 Actor 仅表示操作系统的人，**不代表需要账号、登录或权限模块**。
6. Mermaid 图直接嵌入 Markdown；支持 Mermaid 的阅读器可以显示图形。标准 UML 补充源文件在 [diagrams](diagrams/README.md)，使用 PlantUML 渲染。图源均可版本管理，未依赖联网图片。
7. 18是当前已授权演示初始数据依据；规则算例和自动测试夹具仍与运行库隔离。首次启动不灌入业务；显式命令导入或恢复v2备份用于复演。

推荐阅读顺序：01 → 02 → 03 → 13 → 05 / 06 → 07 / 08 → 09 / 10 → 11 / 12。

## 基线摘要

已有启用商品及完整可用BOM → 销售确认 → 自动生成可调整排产建议 → 确认正式生产单及独立批次 → 按依赖手工开工、调整自身进度 → 总进度逐级汇总 → 销售顶层生产单等权同步 → 完成后双向批次追溯。

Django + Vue + SQLite，单 Docker 容器；无登录权限、库存、产能、采购执行、发货、财务、报废及返工模块。

销售取消：逐销售分配扣量 → 独占批次撤销/共享批次缩量 → BOM子单与原料重展 → 保留完成量重算总进度 → 剩余销售反馈。LOW优先级用于分组，不强制执行顺序；新销售不能追加既有正式计划。
