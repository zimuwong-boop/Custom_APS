# 软件需求规格说明书（SRS / Requirements）

版本：2.0 · 原始基线：2026-10-10 · 修订：2026-10-11 · 状态：当前需求与实现基线。

本文件将已接受的讨论转成可验证条目。所有条目为本期必需；设计细节和默认值另见 [约定登记](14_Change_Risks.md)。需求的测试映射见 [追踪矩阵](10_Traceability.md)。

## 功能需求

| 编号 | 需求与验收口径 |
|---|---|
| FR-001 | 物料分为成品、半成品、原料；编码唯一；维护固定单位及启停状态。引用后禁止修改类型、单位或物理删除，可停用。 |
| FR-002 | BOM 不设置固定业务深度；父项只能为成品/半成品，子项只能为半成品/原料；原料不可有 BOM；制造 BOM 必须非空、用量为正，且禁止直接及间接循环。 |
| FR-003 | BOM 有版本和基准产量，制造子项引用明确的 BOM 版本；正式单据保存完整快照，后续主数据变更不改变历史。 |
| FR-004 | 数量遵循物料单位和精度；整数物料禁止小数输入；计算取整须明示余量并同步展开额外用料，不修改销售需求。 |
| FR-005 | 销售单及销售行可编辑草稿，只能引用已有、启用且具完整可用BOM的成品和半成品；无BOM或仅草稿BOM在创建/编辑时即拒绝，不允许原料或临时产品；数量为正。 |
| FR-006 | 销售单默认优先级可被行覆盖；生成需求时固化行优先级；所有子需求继承；不同优先级不合并；优先级不限制手工执行先后，可先完成LOW。 |
| FR-007 | 销售确认自动进入需求池并生成/刷新未确认建议；缺失或无效 BOM 明确阻止确认，不产生半套正式需求。 |
| FR-008 | 每个需制造的层级都保留生产建议；展开原料仅形成需求明细，不产生原料生产单、库存或采购任务。 |
| FR-009 | 不同销售来源中相同物料、BOM 版本、优先级的需求可以合并；建议保留各来源数量和依赖；类别相同但编码不同不可合并。 |
| FR-010 | 用户可在建议阶段拆分、合并、分配数量和设置各非叶节点子单占比；校验数量守恒、依赖完整及无环。 |
| FR-011 | 确认建议时原子生成生产单、批次、销售分配、生产依赖及原料需求；重复确认不重复创建；失效建议必须先刷新。 |
| FR-012 | 正式生产图可共享子单，支持多父多子；普通结构、BOM 和占比冻结，未开工编辑走撤销重建；销售取消允许依照 BR-010 原地缩量及进度记账。 |
| FR-013 | 仅当所有直接生产子单都已完成才能开始本级生产；原料不参与检查；共享子单整单完成才放行任何父单。 |
| FR-014 | 用户手工开始生产并调整自身进度；未开工、等待子单或已撤销时禁止改自身进度；被撤销批次不得当作已完成子单；共享剩余批次可以因取消后保留完成量达到完成，仍遵守子单门槛。 |
| FR-015 | 非叶节点总进度按直接子单去重等权平均 × 子单占比，再加自身进度 × 剩余占比；实时逐层计算。叶节点常规进度仅用自身进度；发生销售取消后，与保留完成量/剩余计划量下限取大，上限100%。 |
| FR-016 | 占比可为 0% 和 100%；0% 仍须等待子单；100% 且子单全部完成时自动完成，无需手工开工；显示舍入不可决定完成。 |
| FR-017 | 进度回退前检查下游；无手工开工的下游时可修正并重算，包括自动完成节点回退；存在已手工开工下游则拒绝。 |
| FR-018 | 销售单按关联顶层生产单去重后等权平均，销售行也展示；下层节点不重复加入；未覆盖需求不能显示生产完成。 |
| FR-019 | 生产百分比仅表示加工进展，不推导部分可交付数量；销售完成指生产完成，不代表发货、收款。 |
| FR-020 | 每张正式生产单有独立唯一批次；编号包含冻结计划层级；禁止复用及静默改号；图路径解释不同销售下的实际层级。 |
| FR-021 | 保存子批次→父批次、批次→销售行的数量；全额覆盖需求且不重复使用产出；批次使用关系在父单开工/自动或取消记账完成时确认；销售取消按专门动作缩量，保留审计及无效边历史。 |
| FR-022 | 支持销售行/销售单向下追溯所有相关生产批次，及任一批次反查父批次、销售来源；完成后仍可查询历史与替代关系。 |
| FR-023 | 正式计划修改/销售取消前检查所有共享关联；不能删除仍服务其他销售需求的共享单；销售取消按实际分配逐批扣量、递归缩减子单，保留已完成量重算比例，详见 BR-010。 |
| FR-024 | 记录创建、确认、开工、完成时间和关键操作日志，含调整前后、原因及受影响单据；不记录操作人、不建立账号。 |
| FR-025 | 页面展示状态、总进度、自身进度、公式解释、阻塞子单、来源、数量和批次；进度操作后同步刷新相关视图。 |
| FR-026 | 提供显式演示导入命令、初始备份恢复及带确认的清空重置；重置/恢复后旧页面失效。已交付18文档的蒜蓉酱初始场景；当前场景菜单为空，一键业务场景加载和讲解脚本不列为已实现。 |
| FR-027 | 无登录、注册、用户、角色、权限或管理员功能；直接进入演示界面。 |

## 非功能需求

| 编号 | 要求与验收口径 |
|---|---|
| NFR-001 | Django + Vue + SQLite；一个运行容器、一个对外端口；构建阶段工具不计运行容器。 |
| NFR-002 | SQLite 数据卷持久化；容器重启/替换保留数据；备份及恢复流程可重复验证。 |
| NFR-003 | 数量及进度计算不得依赖二进制浮点；避免层层显示舍入误差；深层精度策略见 BR-007。 |
| NFR-004 | 所有写入通过服务端状态、版本、数量校验和事务；幂等重试不能重复建单/报进度；失败不部分落库。 |
| NFR-005 | 无固定 BOM 层级限制；实现采用迭代图遍历。规模超限应明确报错且不部分确认，不能把节点截断当原料。 |
| NFR-006 | 演示验收负载目标：100 张销售单、500 行、2,000 个生产节点、5,000 条依赖；参考 2 vCPU/4 GB，普通查询 p95≤1秒、单次进度重算≤2秒、整批计划≤5秒，均须实测。 |
| NFR-007 | 中文页面、UTC 存储/上海时区显示；数量带单位，百分比最多两位小数；未真实完成时显示上限 99.99%。 |
| NFR-008 | 重置和大范围撤销展示影响并明确确认；错误包含可理解原因和关联节点；不新增权限审批。 |
| NFR-009 | 自动化验证规则、API、数据库约束及关键浏览器流程；支持可重复种子和测试隔离；交付提供结果证据。 |
| NFR-010 | 核心展示离线可运行，不依赖 CDN、外部账号或云服务；构建依赖可联网取得，运行不需要联网。 |
| NFR-011 | 可追溯记录不得随主数据删除而丢失；除明确演示重置外，正式单据和批次均保留。 |
